# Schedule & Training Preferences

## Ideal Weekly Template (aspiration, not a guarantee)
1. Easy ride + chest/back
2. Easy run + leg day
3. Norwegian 4x4 ride + arms
4. Norwegian 4x4 run + push
5. Long ride + pull
6. Long run + leg day
- 1 rest day/week, floating (not fixed to a specific weekday)

## Frequencies
- Running: 3x/week | Lifting: 5x/week | Cycling: 3x/week

## Same-day combining
Comfortable combining a cardio session and a lift on the same day (built into the template above).

## Timing preference
Ideally cardio in the morning, lifting in the evening — currently not achievable due to work
schedule; sessions happen when they fit.

## Real-world adherence
This template is a target, not a log. Missed sessions are usually driven by motivation or
life commitments — no predictable weekly pattern. Do not treat a missed day as a red flag by
itself; compare against actual Strava history to see real patterns.

## Scheduling policy: rolling, not weekly-reset
As of 2026-09-04: switched from a weekly-reset model (restarting the template every Monday) to
a rolling model — if a session is missed, keep progressing through the sequence rather than
restarting the week. Rationale: two years of weekly-reset consistently dropped the aerobic-base/
leg-strength sessions (second leg day, VO2 work, long run/ride) specifically — the work this
rebuild phase depends on — which is a plausible contributor to prior injuries.

Note: this file stores the *policy*; it does not track current position in the rotation. That's
live state without a home yet — infer it from recent Strava activity until a later phase adds
proper tracking.

## Rolling does not create training debt
A missed session's *purpose* may still matter; the athlete does not accumulate an
indefinite queue of workouts they "owe." Each template slot has a **session purpose**
(the training effect it's for) separate from its **session activity** (the literal
template entry) — e.g. "leg day" → lower-body strength/durability; "long run" →
aerobic base + running-specific durability. This is what lets a substitute activity
partially satisfy a slot's purpose without being identical to it.

A rotation turn resolves one of four ways:
- **Retained** — happened as templated.
- **Replaced** — a different activity satisfied the same purpose (e.g. a long walk
  standing in for a long run under a knee flag).
- **Dropped** — the turn passed with nothing satisfying that purpose.
- **Evidence for reconsideration** — a purpose keeps going dropped or replaced by
  something unrelated, turn after turn. This is not a debt to keep rescheduling
  indefinitely — it's a signal (for Weekly Review's existing Pattern Recognition
  step) that the template itself, not just this week's execution, may need to
  change. No fixed count triggers this; it's the same qualitative judgment Weekly
  Review already applies to other patterns.

## Fixed events don't roll
A date-anchored event or constraint (e.g. a scheduled race) is not part of the
rolling rotation — it's a hard calendar anchor, not another turn to fill. Not
currently applicable (no target date set — see `profile/goals.md`), recorded here so
it doesn't need to be retrofitted once one exists.
